**Task 8: `_validate_map_treatment(world_dir, label)`** — Raster map validator
- Validates `map.yaml` treatment layers per spec §2/§5
- Rules:
  - Absent `map.yaml` → `[]` (dag fallback, OK)
  - Present with `treatment: raster` → requires:
    - Non-empty `image` field
    - Complete `provenance` block with `source`, `date`, `archive`, `pd_basis`
    - `node_anchors` entry for every region id from `cartography.yaml`
  - Non-raster treatments → structural check only (must have a valid `treatment` kind)
- Integration: call from `_validate_world` at content-errors collection point

**Task 18: `_validate_weather_zones(world_dir, label)`** — Region climate-zone resolver
- Validates region `weather_zone` declarations per spec §2 A2
- Rules:
  - Every region `weather_zone` must be a key in the world's `weather.yaml` `climate_zones`
  - If any region declares `weather_zone` but world has no `weather.yaml`, error
  - No `weather_zone` anywhere → `[]` (OK)
- Integration: call from `_validate_world` at content-errors collection point

Both validators return `list[str]` with one error per violation. Content invariants are placed in the CI-gated pack validator (not unit tests) by design — validator tests use synthetic fixtures to test the validator CODE (per CLAUDE.md doctrine).

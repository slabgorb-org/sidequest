# Narrative

## Problem Statement
**Problem:** SideQuest has an automated "bot playtester" called Understudy — it joins a real game session and plays through it just like a human would, specifically to catch confusing or broken moments before a real player does. One of its watchdogs, built a few weeks ago, has a single job: catch it when the game accidentally calls the same monster by two different names in the middle of a fight — for example, narrating "Molgrath the Eyeless lunges at you" while the enemy roster on screen still says "Thief." That's exactly the kind of thing that would make a real tabletop veteran stop and say "wait, who am I even fighting?" But when we checked, this watchdog had never actually caught anything — not because the bug it hunts wasn't happening, but because the watchdog itself was broken. It was looking for a shape of screen content that doesn't exist in the real game, so it silently reported "nothing wrong" on every single session, whether something was wrong or not.

**Why it matters:** This isn't a cosmetic gap — it's a blind spot in our safety net. Earlier this sprint we shipped several fixes specifically to stop enemies from getting split into two identities mid-fight. The only automated way we have to prove those fixes actually hold up in a live game is this watchdog. If it's silently doing nothing, we have zero automated confidence those fixes work — and any future regression of the same bug could ship to players undetected. A guard that always says "all clear" is worse than no guard at all, because it creates false confidence.

## What Changed
Think of the game screen as having two layers: the part a player sees with their eyes, and an invisible "accessibility layer" underneath that describes the same content in plain structured terms — the same layer that lets screen-reading software describe a webpage to someone who can't see it. Our automated bot reads that invisible layer, not pixels, to understand what's happening in a session.

The investigation found the invisible layer was essentially blank in the two places that mattered: the enemy roster had no label marking it as "this is the Enemies list," and the narration feed (the scrolling story text) had no label marking it as "this is a live updating log." The watchdog was built assuming those labels existed — they didn't — so it always came back empty-handed.

We fixed it in three parts:
1. **Added the missing labels to the actual game screen.** The enemy roster is now explicitly marked as an "Enemies" region with each foe as a distinct list entry, and the narration feed is now explicitly marked as a live log. This is invisible to a player looking at the screen — no visual change — but it's now real content assistive technology (and our bot) can read.
2. **Taught the bot to read the labels correctly.** Once real labels existed, we found the bot's reading logic didn't understand the exact shape the browser produces (story text nested a layer deeper than expected), so it still came up empty. We fixed that parsing.
3. **Fixed a subtle mislabeling bug.** The enemy's portrait icon has a single-letter monogram (like "T" for Thief) purely for visual flair. The bot was accidentally reading that letter as part of the creature's name ("T Thief" instead of "Thief"), which could have triggered false alarms later. We made the monogram invisible to assistive tools so the bot reads the clean name.

Along the way, our reviewer caught something worth calling out: an early version of the fix had a subtle flaw where a stray blank space in the game's output could make the watchdog go silently dark again — the exact failure mode we were trying to eliminate. That got caught and closed before shipping, and the team added tests specifically designed to prove it stays closed (they even deliberately broke the fix to confirm the tests would catch it, then restored it).

## Why This Approach
We chose to fix this at the source rather than patch around it. The tempting shortcut would have been to make the bot smarter about guessing at content that isn't really there — but that's fragile and dishonest about what's actually on screen. Instead, we added the real, permanent accessibility labels to the game UI itself. That's a better outcome on its own (real accessibility support for real assistive technology users), and it means the bot is now reading the truth instead of working around a gap.

We also fixed the underlying "how do I read the story text" logic in one shared place rather than special-casing it for this one watchdog. That means every other automated watchdog Understudy has — or will have — that needs to read narration text benefits from this fix automatically, not just the one we were chasing.

Finally, this went through a genuinely adversarial review cycle, not a rubber stamp. The first review round rejected the work — it found the silent-failure risk described above, plus a gap where the test fixture didn't match what the real screen produces closely enough to prove the fix actually works. The team reworked it, and the second review independently re-verified every fix by deliberately breaking each one and confirming the tests caught it, before approving. That's the level of scrutiny we want on anything touching a safety-net system.
